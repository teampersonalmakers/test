# fcp-autocut — 파이널컷 자동 가편집

사용자는 유튜버이고 코딩을 하지 않는다. **사용자에게 하는 모든 말은 쉬운 한국어, 개발 용어 금지**
(예: "edits.json" → "편집 목록", "candidates" → "자를 후보", "DTD 검증" → "파이널컷 규격 검사").

## 절대 원칙

1. **원본 영상은 읽기만 한다.** 수정·복사·변환 저장·합친 영상 만들기 금지. 원본 폴더에 생기는 건
   `<제목>_가편집.fcpxml`, `<제목>_편집리포트.md` 두 개뿐. 중간 파일은 전부 `~/.local/share/fcp-autocut/`.
2. **확신 없는 삭제를 조용히 하지 않는다.** 애매하면 남기고 파이널컷 할 일 마커(🔴)를 꽂는다.
3. 더듬기 확정·베스트 테이크 선택·잡담 판별은 **별도 API 없이 내가(Claude) 대본을 읽고** 한다.
   스크립트는 계산·후보 추출·파일 생성만 한다.
4. 여러 영상에 걸친 같은 이야기는 지우지 말고 **사용자에게 어느 쪽을 남길지 묻는다.**
5. 수치는 `config/presets.yaml`에만 있다. 코드에 숫자를 넣지 않는다.

## 준비

```zsh
SK="$HOME/.claude/skills/fcp-autocut"; S="${SK}/scripts"
PY="$HOME/.local/share/fcp-autocut/venv/bin/python"
zsh "${S}/setup.sh" --check
```
- 경로는 반드시 큰따옴표로 감싸고 `${var}` 형태로 쓴다(공백·한글 경로). 여러 경로를 다룰 땐
  `tr '\n' '\0' < batch.txt | xargs -0 ...`.
- `NOT_READY`면 무엇이 없는지 쉬운 말로 알리고:
  - ffmpeg 없음 → "터미널에 `brew install ffmpeg`를 실행해 주세요" 안내(직접 설치하지 않음).
  - 가상환경/패키지 없음 → **동의를 받은 뒤** `zsh "${S}/setup.sh" --install`.
  - 맥이 아니거나 애플 실리콘이 아니면 **중단**하고 알린다.

## 작업 순서 (가편집 요청)

### 1. 시작 전 확인 (모르면 묻기)
- **포맷**: 브이로그 / 나레이션 / 인터뷰. 사용자가 말하지 않았으면 시작 전에 묻는다.
- **제목**: 결과 파일 이름이 된다. 말하지 않았으면 폴더 이름 등으로 제안하고 확인.
- **영상 목록과 순서**: 사용자가 준 정확한 경로 그대로 쓴다. 파일 번호로 추측(glob)하지 않는다.
  폴더만 줬다면 `ls`로 영상 파일 목록을 보여 주고 확인받는다. 순서를 안 정했으면 `--sort-name`을 쓰고
  "파일 이름순(촬영순)으로 이어 붙였어요"라고 알린다.
- **채널 노트**: `~/.local/share/fcp-autocut/channel/채널노트.md`가 있으면 먼저 읽는다
  (자주 쓰는 오프닝 멘트·동행자 이름·고유명사·편집 리듬 → 판단에 반영).

### 2. 영상 확인
```zsh
"${PY}" "${S}/probe.py" --title "${T}" --format vlog --init "/경로/A.MP4" "/경로/B.MP4"   # [--sort-name]
```
채널 판단 결과(모노 / 좌우 분리 / 한쪽만)를 근거 수치와 함께 한두 줄로 보고한다.
**인터뷰 + 좌우 분리**면 어느 쪽이 진행자인지 묻거나 대본을 보고 추정해 확인받은 뒤
작업 폴더에 `roles.json` 저장: `{"L": "진행자", "R": "출연자"}` (저장 후 analyze 재실행).
인터뷰가 모노면 화자를 기계적으로 나눌 수 없다 → 대본 흐름(질문/답변)으로 내가 판단하고,
확신 없으면 진행자 발화라도 자르지 않고 마커.

### 3. 받아쓰기
```zsh
"${PY}" "${S}/transcribe.py" --title "${T}"
```
- 종료 코드 3 + `NEED_MODEL_DOWNLOAD` → **"받아쓰기 모델(약 1.6GB)을 한 번 내려받아야 해요. 받을까요?"** 라고
  묻고, 동의하면 `--allow-download`를 붙여 다시 실행. 동의 없이 절대 받지 않는다.
- 걸리는 시간은 영상 길이의 약 1/3~1/4. 전체가 5분을 넘으면 **백그라운드로 실행**하고 예상 시간을 알린 뒤,
  작업 폴더의 `progress.json`을 가끔 확인해 진행 상황을 짧게 알려 준다.
- 끊겨도 같은 명령을 다시 실행하면 끝난 조각부터 이어서 한다. 이미 받아쓴 영상은 건너뛴다.

### 4. 후보 계산
```zsh
"${PY}" "${S}/analyze.py" --title "${T}"
```
경고(배경 소음과 말소리 차이 15dB 미만 등)는 사용자에게 그대로 전달한다.

### 5. 대본 읽고 판단 (가장 중요)
```zsh
"${PY}" "${S}/view.py" --title "${T}" --suggest            # 확신도 높은 후보로 초안 생성
"${PY}" "${S}/view.py" --title "${T}" --from 1 --to 150     # 150문장씩 끝까지 전부 읽기
"${PY}" "${S}/view.py" --title "${T}" --groups              # 반복 묶음만
```
대본을 **처음부터 끝까지** 읽고, 초안(`edits.draft.json`, `notes.draft.json`)을 검토·수정해서
작업 폴더에 `edits.json`, `notes.json`으로 저장한다. 초안을 그대로 복사하지 않는다.

**edits.json** (자를 것만):
```json
{"A001": ["12", "15", "20:0-2", "@83.20-83.75"], "A002": ["*"]}
```
- `"12"` 12번 문장 통째로(앞뒤 멈춤까지 자연스럽게 정리) · `"20:0-2"` 20번 문장의 0~2번 단어
- `"*"` 영상 전체 · `"@83.20-83.75"` 시간 범위(초, 받아쓰기에 없는 더듬은 소리 등)
- 문장 번호는 전체 영상에서 고유하다. 무음 컷은 자동이라 적지 않는다.

**notes.json** (판단 기록 — 리포트와 마커에 쓰인다):
```json
{"reasons": {"A001|12": {"type": "retake", "reason": "3번 반복 중 마지막이 끝맺음 온전"},
             "A001|31": {"type": "offtalk", "reason": "마이크 확인 대화"}},
 "keep": {"A001|40": "자르기 후보였지만 동행자 리액션이라 유지"},
 "dismiss": ["c57"],
 "markers": [{"clip": "A001", "ref": "44", "note": "자막 강조 추천", "done": false}],
 "retake_choices": [{"group": "g3", "kept": "18", "reason": "2번째가 내용이 더 온전"}],
 "questions": ["A002 앞부분과 A003 앞부분이 같은 이야기 — 어느 쪽을 남길까요?"]}
```
- type: `disfluency` `filler` `retake` `offtalk` `other`
- **자르기 후보(✂)를 edits에 넣지 않기로 했으면 반드시 `keep`에 이유를 적는다.** 안 적으면 build가
  확인용 🔴 마커를 꽂는다(조용히 남기지 않기 위한 안전장치).
- 📍 마커 후보 중 대본을 보고 확실히 문제없는 것은 `dismiss`에 넣어 마커를 줄인다.

#### 판단 규칙
- **확신도**: 0.8 이상 자르기 / 0.5~0.8 남기고 할 일 마커 / 0.5 미만 무시 (presets `confidence`).
  내 판단도 같은 기준. 대본으로 확신이 서면 후보 확신도와 달라도 되지만 이유를 `reasons`에 남긴다.
- **반복 테이크**: 같은 내용을 여러 번 말했으면 기본은 **마지막 테이크**를 남긴다. 앞 테이크가 점수가
  뚜렷하게 높거나 내용이 더 온전하면 그걸 남기고 `retake_choices`에 이유를 쓴다. 말하다 끊긴 시작은 삭제.
  "바로 이어서 반복"은 확신도가 높다. 멀리 떨어진 반복은 의도적인 강조일 수 있으니 흐름을 본다.
- **문장 안 더듬기**: 단어 범위만 삭제(`"20:0-2"`). "그 그래서"의 "그", "어/음" 같은 확실한 군말.
  "이제/그/막/약간"처럼 뜻이 있는 말은 문맥상 군말이 확실할 때만.
- **소리는 있는데 받아쓴 글자가 없는 구간**(`받아쓰기에 없는 말소리`): 받아쓰기가 더듬은 말을 생략한
  흔적일 수 있다. 앞뒤 단어와 함께 보고 더듬기로 확신하면 `@시작-끝`으로 자르고, 아니면 마커.
- **촬영 중 잡담**: "다시 갈게", "마이크 켜졌어?", "이거 자막에 넣자" 같은 제작 대화는 삭제.
  함께 있는 사람과의 자연스러운 리액션은 유지.
- **영상을 통째로 다시 찍은 경우**: 앞 영상 전체 `"*"`. (다음 영상과 대부분 겹치는지 대본으로 확인)
- **여러 영상에 걸친 같은 이야기**: 지우지 말고 `questions`에 적고 사용자에게 묻는다.
- **받아쓰기 오류(🚫)**: 글자만 무시된 것. 그 구간의 소리는 무음/현장음 규칙대로 처리된다.

#### 포맷별 규칙
| | 나레이션 | 브이로그 | 인터뷰 |
|---|---|---|---|
| 무음 | 촘촘하게(숨소리 포함) | 말하는 구간 안에서만, 현장음 장면 보호, 4초 넘는 무음은 마커 | 느슨하게, 답변 전 생각하는 멈춤 일부 유지 |
| 더듬기 | 적극 삭제 | 적극 삭제 | 인터뷰이 발화는 마커만, 진행자 발화는 삭제 가능 |
| 반복 | 핵심 기능 | 오프닝·마무리 위주 | 질문을 다시 한 경우 정도 |
| 잡담 | 삭제 | 삭제, 동행자 리액션 유지 | 촬영 세팅 대화만 삭제 |

브이로그의 현장음 장면(♪ 🛡 유지: 요리·거리·파도 소리)은 내 판단으로도 자르지 않는다.
말이 하나도 없는 영상(풍경 컷)은 브이로그에서 통째로 남긴다.

### 6. FCPXML 만들기
```zsh
"${PY}" "${S}/build.py" --title "${T}"
```
- 파이널컷 앱 안의 최신 규격 파일로 검사를 통과해야만 원본 폴더에 저장된다.
- 원본 폴더에 쓸 수 없으면(SD카드 잠금 등) `--out-dir`로 다른 폴더를 사용자에게 제안.

### 7. 결과 보고 (채팅)
다음 순서로 짧게:
1. 저장 위치(두 파일)와 "파이널컷에서 **파일 > 가져오기 > XML**로 열면 돼요"
2. 몇 분 → 몇 분 (몇 % 줄였는지)
3. 주요 삭제 예시 3~5개 (`[번호] "문장" — 이유`)
4. 판단이 필요한 항목(질문, 🔴 마커 개수와 대표 예)
5. 주의사항: 원본을 옮기면 연결이 끊김 / 다시 가져오면 이벤트 이름에 v2·v3이 붙음(이전 것은 지워도 됨) /
   말끝이 먹힌 곳은 오디오 페이드로 다듬기
6. "살리고 싶은 번호를 말해 주세요"

## 후속 요청
- **"N번 살려줘"**: `edits.json`에서 `"N"`과 `"N:..."`를 빼고(`keep`에 "사용자 요청" 기록) **build.py만** 다시.
  받아쓰기·분석은 다시 하지 않는다.
- **"더 촘촘하게/느슨하게"**: presets.yaml의 해당 포맷 `silence` 값(`min_silence_sec`, `pad_*`)을 조정하고
  어떤 값을 얼마나 바꿨는지 쉬운 말로 알린 뒤 analyze.py → build.py. (받아쓰기 재실행 없음)
  ⚠️ `sentence` 값을 바꾸면 문장 번호가 바뀌므로 edits.json을 다시 판단해야 한다.
- **"이 단어 자꾸 틀려"**: `config/vocab.txt`에 추가 → 해당 영상만 받아쓰기 다시(`--only`, 기존 결과 파일 삭제 후).

## 유튜브 영상으로 배우기
사용자가 자기 유튜브 링크를 주며 분석·학습을 요청하면:
1. 포맷을 모르면 묻는다. yt-dlp가 없으면 동의 후 `zsh "${S}/setup.sh" --youtube`.
2. `"${PY}" "${S}/learn.py" add "<링크>" --format vlog` (화면 전환 속도까지 보려면 `--video`).
   받은 오디오는 임시로만 쓰고 지워진다. 모델 다운로드 규칙은 받아쓰기와 같다.
3. 출력된 `VIDEO_JSON`을 읽는다(대본 `stats.text`, 직접 올린 자막 `subtitle_text`, 설명, 챕터).
4. `~/.local/share/fcp-autocut/channel/채널노트.md`를 만들거나 갱신한다:
   주제·말투·자주 쓰는 오프닝/마무리 멘트·동행자·고유명사·편집 리듬(문장 사이 멈춤, 남겨 두는 군말)·
   이 채널에서 '살려야 하는 말'의 특징. 영상이 쌓일수록 공통점 위주로 다듬는다. 추측은 추측이라고 적는다.
5. `"${PY}" "${S}/learn.py" summary`로 설정값 제안·고유명사 후보를 보고, **사용자에게 보여 주고 동의를 받은 뒤에만**
   presets.yaml / vocab.txt를 바꾼다.
- 할 수 있는 것: 완성본의 말 리듬·멈춤 길이·남긴 군말·자주 쓰는 표현·오프닝/마무리 패턴·화면 전환 빈도.
- 할 수 없는 것: 화면 내용(무엇이 찍혔는지) 이해, 비공개·멤버십 영상, 원본 없이 "무엇을 잘랐는지" 알아내기.

## 문제 해결
- 파이널컷에서 클립이 빨간 화면 → 원본을 옮겼거나 이름이 바뀜. 원래 위치로 되돌리거나 파이널컷의
  "파일 다시 연결"을 안내.
- 규격 검사 실패 → 오류 내용을 읽고 원인을 고친다(사용자에게는 "파일 형식을 고치는 중"이라고만).
- 받아쓰기가 너무 틀림 → 시끄러운 현장일 가능성. 경고 수치를 알려 주고 vocab.txt 보강 제안.
- 테스트: `"${PY}" -m pytest "${SK}/tests" -q` (pytest는 `setup.sh --dev`)
