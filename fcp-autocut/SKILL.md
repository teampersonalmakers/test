# fcp-autocut — 파이널컷 자동 가편집

사용자는 유튜버이고 코딩을 하지 않는다. **사용자에게 하는 모든 말은 쉬운 한국어, 개발 용어 금지**
(예: "edits.json" → "편집 목록", "candidates" → "자를 후보", "DTD 검증" → "파이널컷 규격 검사").

## 절대 원칙

1. **원본 영상은 읽기만 한다.** 수정·복사·변환 저장·합친 영상 만들기 금지. 원본 폴더에 생기는 건
   `<제목>_가편집.fcpxml`, `<제목>_편집리포트.md` 두 개뿐. 중간 파일은 전부 `~/.local/share/fcp-autocut/`.
2. **확신 없는 삭제를 조용히 하지 않는다.** 애매하면 남기고 파이널컷 할 일 마커(🔴)를 꽂는다.
3. 더듬기 확정·베스트 테이크 선택·잡담 판별은 **별도 API 없이 내가(Claude) 대본을 읽고** 한다.
   스크립트는 계산·후보 추출·파일 생성만 한다.
4. 여러 영상에 걸친 같은 이야기는 지우지 말고 **사용자에게 어느 쪽을 남길지 묻는다.**
5. 수치는 `config/presets.yaml`(기본)과 `~/.local/share/fcp-autocut/my_presets.yaml`(피드백으로 배운 내 설정, 기본 위에 덮어씀)에만 있다.
   코드에 숫자를 넣지 않는다. 조정은 항상 my_presets.yaml에 한다.

## 준비

모든 실행은 **`~/.local/share/fcp-autocut/bin/fcp`** 하나로 한다(이 형태 그대로 써야 허용 목록에 걸려 확인창이 안 뜬다.
변수로 감싸거나 절대경로로 바꿔 쓰지 않는다).
```zsh
~/.local/share/fcp-autocut/bin/fcp setup --check
```
- 폴더 안 영상 목록: `~/.local/share/fcp-autocut/bin/fcp videos "/폴더"` (이름순, .LRF 제외)
- 파이널컷으로 열기: `~/.local/share/fcp-autocut/bin/fcp open "/결과.fcpxml"`
- 지난번 포맷: `~/.local/share/fcp-autocut/bin/fcp prefs` / 저장: `... prefs vlog`
- 사용자가 영상을 **첨부(업로드)**하려다 "30MB" 오류가 났다면: 업로드가 필요 없다고 알리고, Finder에서
  영상 선택 → **Option+Command+C**(경로 복사) → 붙여넣기를 안내한다.
- 경로는 반드시 큰따옴표로 감싸고 `${var}` 형태로 쓴다(공백·한글 경로). 여러 경로를 다룰 땐
  `tr '\n' '\0' < batch.txt | xargs -0 ...`.
- `NOT_READY`면 무엇이 없는지 쉬운 말로 알리고:
  - ffmpeg 없음 → "터미널에 `brew install ffmpeg`를 실행해 주세요" 안내(직접 설치하지 않음).
  - 가상환경/패키지 없음 → **동의를 받은 뒤** `~/.local/share/fcp-autocut/bin/fcp setup --install`.
  - 맥이 아니거나 애플 실리콘이 아니면 **중단**하고 알린다.

## 작업 순서 (가편집 요청)

### 1. 시작 전 확인 — 질문은 최소로
사용자는 "영상 끌어다 놓기 → 컷편집해줘 → 파이널컷에서 확인"만 원한다. 묻지 않아도 되는 건 묻지 않는다.
- **포맷**: 말했으면 그대로. 안 말했으면 `fcp prefs`의 `last_format`을 쓰고
  "지난번처럼 브이로그로 할게요(다르면 말씀해 주세요)"라고 한 줄만 알리고 바로 진행. 기록이 없을 때(처음)만 묻는다.
  작업이 끝나면 `fcp prefs <포맷>`으로 저장한다.
- **제목**: 묻지 않는다. 첫 영상의 폴더 이름(폴더가 "Downloads"·"Desktop"·"Movies"처럼 일반적이면 첫 파일 이름)으로
  정하고 결과 보고 때 알린다.
- **영상 목록과 순서**: 사용자가 준(끌어다 놓은) 정확한 경로 그대로 쓴다. 파일 번호로 추측(glob)하지 않는다.
  **폴더를 주면 폴더 경로를 그대로 `--init`에 넣고 `--sort-time`**(영상에 기록된 촬영 시각순)을 쓴다. `.MP4`/`.MOV`만
  자동으로 고르고(.LRF·.THM·사진 제외), 읽을 수 없는(복사 덜 됨·깨진) 파일은 빼고 진행한다. 파일 이름은 촬영 순서가
  아닐 수 있으니 이름순(`--sort-name`)은 사용자가 원할 때만. 시작 전에 "영상 N개, 합계 ○분, 촬영 시각순, 받아쓰기 약 ○분"을
  한 줄로 알리고 바로 진행한다. 빠진 파일·복사본 경고가 있으면 함께 알린다.
  파일을 하나씩 준 경우엔 준 순서 그대로(사용자가 순서를 신경 쓰지 않았으면 `--sort-time`).
- **받아쓰기 모델·설치 동의**처럼 꼭 필요한 것만 묻는다.
- **내 스타일 불러오기(매번)**: `~/.local/share/fcp-autocut/편집취향.md`가 있으면 먼저 읽고 그 규칙을 이번 판단에
  그대로 적용한다. `~/.local/share/fcp-autocut/bin/fcp feedback summary --format <포맷>`도 실행해 최근 되살림 경향을 확인한다
  (예: "브이로그 반복 컷을 자주 되살림" → 이번엔 반복을 더 보수적으로).
- **채널 노트**: `~/.local/share/fcp-autocut/channel/채널노트.md`가 있으면 먼저 읽는다
  (자주 쓰는 오프닝 멘트·동행자 이름·고유명사·편집 리듬 → 판단에 반영).

### 2~4. 준비 한 번에 (권장)
```zsh
~/.local/share/fcp-autocut/bin/fcp prepare --title "${T}" --format vlog --init "/경로/폴더" --sort-time   # 또는 파일 경로 여러 개
```
영상 확인 → 받아쓰기 → 후보 계산 → 초안까지 한 번에 하고 `PREPARE_DONE`을 출력한다. 이미 끝난 단계는
건너뛰므로 중간에 멈춰도 같은 명령(두 번째부터는 `--init` 없이)으로 이어서 실행하면 된다.
종료 코드 3이면 모델 동의 절차(아래 3번), 길면 백그라운드 실행 규칙(아래 3번)을 똑같이 따른다.
아래 2~4번은 단계별로 따로 돌릴 때의 설명이다.

### 2. 영상 확인
```zsh
~/.local/share/fcp-autocut/bin/fcp probe --title "${T}" --format vlog --init "/경로/폴더" --sort-time   # 또는 파일 경로 여러 개
```
채널 판단 결과(모노 / 좌우 분리 / 한쪽만)를 근거 수치와 함께 한두 줄로 보고한다.
**인터뷰 + 좌우 분리**면 어느 쪽이 진행자인지 묻거나 대본을 보고 추정해 확인받은 뒤
작업 폴더에 `roles.json` 저장: `{"L": "진행자", "R": "출연자"}` (저장 후 analyze 재실행).
인터뷰가 모노면 화자를 기계적으로 나눌 수 없다 → 대본 흐름(질문/답변)으로 내가 판단하고,
확신 없으면 진행자 발화라도 자르지 않고 마커.

### 3. 받아쓰기
```zsh
~/.local/share/fcp-autocut/bin/fcp transcribe --title "${T}"
```
- 종료 코드 3 + `NEED_MODEL_DOWNLOAD` → **"받아쓰기 모델(약 1.6GB)을 한 번 내려받아야 해요. 받을까요?"** 라고
  묻고, 동의하면 `--allow-download`를 붙여 다시 실행. 동의 없이 절대 받지 않는다.
- 걸리는 시간은 영상 길이의 약 1/3~1/4. 전체가 5분을 넘으면 **백그라운드로 실행**하고 예상 시간을 알린 뒤,
  작업 폴더의 `progress.json`을 가끔 확인해 진행 상황을 짧게 알려 준다.
- 끊겨도 같은 명령을 다시 실행하면 끝난 조각부터 이어서 한다. 이미 받아쓴 영상은 건너뛴다.

### 4. 후보 계산
```zsh
~/.local/share/fcp-autocut/bin/fcp analyze --title "${T}"
```
경고(배경 소음과 말소리 차이 15dB 미만 등)는 사용자에게 그대로 전달한다.

### 5. 대본 읽고 판단 (가장 중요)
```zsh
~/.local/share/fcp-autocut/bin/fcp view --title "${T}" --suggest            # 확신도 높은 후보로 초안 생성
~/.local/share/fcp-autocut/bin/fcp view --title "${T}" --from 1 --to 150     # 150문장씩 끝까지 전부 읽기
~/.local/share/fcp-autocut/bin/fcp view --title "${T}" --groups              # 반복 묶음만
```
대본을 **처음부터 끝까지** 읽고, 초안(`edits.draft.json`, `notes.draft.json`)을 검토·수정해서
작업 폴더에 `edits.json`, `notes.json`으로 저장한다. 초안을 그대로 복사하지 않는다.
- 전체 30분 이하: 전부 읽는다(150~300문장씩).
- 30분 초과: `--focus`(후보 있는 문장 + 앞뒤 1문장)를 먼저 끝까지 읽고 판단한 뒤, 전체 대본은 300문장씩
  훑으며 키워드로 안 잡힌 제작 대화·통째로 다시 찍은 구간만 추가로 찾는다.

**edits.json** (자를 것만):
```json
{"A001": ["12", "15", "20:0-2", "@83.20-83.75"], "A002": ["*"]}
```
- `"12"` 12번 문장 통째로(앞뒤 멈춤까지 자연스럽게 정리) · `"20:0-2"` 20번 문장의 0~2번 단어
- `"*"` 영상 전체 · `"@83.20-83.75"` 시간 범위(초, 받아쓰기에 없는 더듬은 소리 등)
- 문장 번호는 전체 영상에서 고유하다. 무음 컷은 자동이라 적지 않는다.

**notes.json** (판단 기록 — 리포트와 마커에 쓰인다):
```json
{"reasons": {"A001|12": {"type": "retake", "reason": "3번 반복 중 마지막이 끝맺음 온전"},
             "A001|31": {"type": "offtalk", "reason": "마이크 확인 대화"}},
 "keep": {"A001|40": "자르기 후보였지만 동행자 리액션이라 유지"},
 "dismiss": ["c57"],
 "markers": [{"clip": "A001", "ref": "44", "note": "자막 강조 추천", "done": false}],
 "retake_choices": [{"group": "g3", "kept": "18", "reason": "2번째가 내용이 더 온전"}],
 "questions": ["A002 앞부분과 A003 앞부분이 같은 이야기 — 어느 쪽을 남길까요?"]}
```
- type: `disfluency` `filler` `retake` `offtalk` `other`
- **자르기 후보(✂)를 edits에 넣지 않기로 했으면 반드시 `keep`에 이유를 적는다.** 안 적으면 build가
  확인용 🔴 마커를 꽂는다(조용히 남기지 않기 위한 안전장치).
- 📍 마커 후보 중 대본을 보고 확실히 문제없는 것은 `dismiss`에 넣어 마커를 줄인다.
- 🔴 할 일 마커는 결과 1분당 2개(presets `markers.max_todo_per_min`)를 넘으면 확신도 높은 것만 꽂히고 나머지는
  리포트의 "마커로 꽂지 않은 확인 후보"에만 남는다. 그러니 내가 판단할 수 있는 건 최대한 판단해서
  자르거나(`edits`) 지우는(`dismiss`) 쪽으로 정리해 마커를 정말 사용자가 봐야 할 것만 남긴다.

#### 판단 규칙
- **확신도**: 0.8 이상 자르기 / 0.5~0.8 남기고 할 일 마커 / 0.5 미만 무시 (presets `confidence`).
  내 판단도 같은 기준. 대본으로 확신이 서면 후보 확신도와 달라도 되지만 이유를 `reasons`에 남긴다.
- **반복 테이크**: 같은 내용을 여러 번 말했으면 기본은 **마지막 테이크**를 남긴다. 앞 테이크가 점수가
  뚜렷하게 높거나 내용이 더 온전하면 그걸 남기고 `retake_choices`에 이유를 쓴다. 말하다 끊긴 시작은 삭제.
  "바로 이어서 반복"은 확신도가 높다. 멀리 떨어진 반복은 의도적인 강조일 수 있으니 흐름을 본다.
- **문장 안 더듬기**: 단어 범위만 삭제(`"20:0-2"`). "그 그래서"의 "그", "어/음" 같은 확실한 군말.
  "이제/그/막/약간"처럼 뜻이 있는 말은 문맥상 군말이 확실할 때만.
- **소리는 있는데 받아쓴 글자가 없는 구간**(`받아쓰기에 없는 말소리`): 받아쓰기가 더듬은 말을 생략한
  흔적일 수 있다. 앞뒤 단어와 함께 보고 더듬기로 확신하면 `@시작-끝`으로 자르고, 아니면 마커.
- **촬영 중 잡담**: "다시 갈게", "마이크 켜졌어?", "이거 자막에 넣자" 같은 제작 대화는 삭제.
  함께 있는 사람과의 자연스러운 리액션은 유지.
- **영상을 통째로 다시 찍은 경우**: 앞 영상 전체 `"*"`. (다음 영상과 대부분 겹치는지 대본으로 확인)
- **여러 영상에 걸친 같은 이야기**: 지우지 말고 `questions`에 적고 사용자에게 묻는다.
- **받아쓰기 오류(🚫)**: 글자만 무시된 것. 그 구간의 소리는 무음/현장음 규칙대로 처리된다.

#### 포맷별 규칙
| | 나레이션 | 브이로그 | 인터뷰 |
|---|---|---|---|
| 무음 | 촘촘하게(숨소리 포함) | 말하는 구간 안에서만, 현장음 장면 보호, 4초 넘는 무음은 마커 | 느슨하게, 답변 전 생각하는 멈춤 일부 유지 |
| 더듬기 | 적극 삭제 | 적극 삭제 | 인터뷰이 발화는 마커만, 진행자 발화는 삭제 가능 |
| 반복 | 핵심 기능 | 오프닝·마무리 위주 | 질문을 다시 한 경우 정도 |
| 잡담 | 삭제 | 삭제, 동행자 리액션 유지 | 촬영 세팅 대화만 삭제 |

브이로그의 현장음 장면(♪ 🛡 유지: 요리·거리·파도 소리)은 내 판단으로도 자르지 않는다.
말이 하나도 없는 영상(풍경 컷)은 브이로그에서 통째로 남긴다.

### 6. FCPXML 만들기
```zsh
~/.local/share/fcp-autocut/bin/fcp build --title "${T}"
```
- 파이널컷 앱 안의 최신 규격 파일로 검사를 통과해야만 원본 폴더에 저장된다.
- 원본 폴더에 쓸 수 없으면(SD카드 잠금 등) `--out-dir`로 다른 폴더를 사용자에게 제안.

### 7. 파이널컷에 바로 열기 + 결과 보고
- 만들고 나면 **바로 파이널컷으로 연다**: `~/.local/share/fcp-autocut/bin/fcp open "<결과 .fcpxml 경로>"`
  (파이널컷의 XML 가져오기 창이 뜨면 사용자는 보관함만 고르면 된다. 열기가 실패하면
  "파일 > 가져오기 > XML로 열어 주세요"라고 안내.)
- 채팅 보고는 짧게(5줄 안팎):
  1. "파이널컷에 열었어요" + 몇 분 → 몇 분
  2. 주요 삭제 예시 2~3개 (`[번호] "문장" — 이유`)
  3. 🔴 확인할 곳 개수, 질문이 있으면 질문
  4. "살리고 싶은 번호나 '더 촘촘하게/느슨하게'를 말해 주세요"
- 자세한 내용(삭제 목록·주의사항)은 리포트 파일에 있으니 채팅에 길게 쓰지 않는다. 주의사항은 첫 사용 때만 한 번 알린다
  (원본을 옮기면 연결이 끊김 / 다시 만들면 이벤트 이름에 v2·v3이 붙음).

## 후속 요청 = 학습 (피드백할수록 내 스타일로)
사용자가 결과를 보고 같은 대화에 고칠 점을 말하면, **고치고 → 기록하고 → 규칙으로 정리**한다. 매번 세 단계를 모두 한다.

1. **고치기**
   - "N번 살려줘" / "3분 20초쯤 잘린 말 살려줘": 리포트의 "(결과 ○○ 부근)"으로 번호를 찾아 `edits.json`에서
     `"N"`·`"N:..."`를 빼고(`keep`에 "사용자 요청") build만 다시 → 파이널컷으로 다시 연다.
   - "이것도 잘라줘": 해당 번호를 edits에 넣고 build.
   - "더 촘촘하게/느슨하게": 이번 작업은 바로 반영(아래 '내 설정'에 포맷별 값 조정) → analyze → build.
   - "이 단어 자꾸 틀려": `~/.local/share/fcp-autocut/my_vocab.txt`에 추가 → 그 영상만 다시 받아쓰기(`--only`).
2. **기록하기** (고칠 때마다, 사용자 말 원문 그대로)
   ```zsh
   ~/.local/share/fcp-autocut/bin/fcp feedback --title "<제목>" add --kind restore --refs "12,15:0-2" --request "<사용자가 한 말>"
   ```
   kind: `restore`(살려줘) · `cut`(더 잘라줘) · `tighter` · `looser` · `other`. refs를 주면 그 말이 어떤 유형
   (반복·더듬기·군말·잡담)으로 잘렸었는지와 문장이 자동으로 함께 저장된다. 편집 결과 통계는 build가 자동 저장.
3. **규칙으로 정리하기** — `~/.local/share/fcp-autocut/편집취향.md`를 갱신한다.
   - 한 번의 요청이라도 이유가 분명하면 규칙으로 적는다(예: "동행자 '민지'의 리액션은 남긴다",
     "오프닝 인사 '안녕하세요 커밍쏜입니다'는 반복이어도 마지막 것 하나는 꼭 남긴다", "'진짜'로 시작하는 감탄은 살린다").
   - 형식: `## 브이로그` / `## 나레이션` / `## 인터뷰` / `## 공통` 아래에 `- 규칙 (근거: 날짜, 무슨 요청)`.
   - 서로 부딪히는 규칙은 최근 것을 따르고 옛 규칙은 지운다. 추측은 "(추정)"이라고 적는다.
   - 사용자에게는 한 줄로 알린다: "다음부터 ○○는 남길게요."

### 숫자 설정까지 맞추기
- `~/.local/share/fcp-autocut/bin/fcp feedback summary`가 "🔧 설정 조정 제안"을 내면(같은 유형을 자주 되살림, '더 촘촘하게'가 반복됨 등)
  **쉬운 말로 한 번 묻고**, 동의하면 `~/.local/share/fcp-autocut/my_presets.yaml`에 그 포맷 값만 적는다
  (presets.yaml과 같은 구조, 바꿀 값만. 예: `vlog: {silence: {pad_after_sec: 0.1}}`). 스킬 기본 파일은 고치지 않는다.
- 군말·제작대화 사전도 내 것만 따로: `my_fillers.txt`(`[확실]`/`[애매]`에 추가, 자주 되살린 말은 `[빼기]`),
  `my_offtalk.txt`, `my_vocab.txt`. 전부 `~/.local/share/fcp-autocut/`에 있어 스킬을 업데이트해도 유지된다.
- 이렇게 바꾼 내용도 편집취향.md 맨 아래 "설정 변경 기록"에 날짜와 이유를 남긴다.

## 유튜브 영상으로 배우기
사용자가 자기 유튜브 링크를 주며 분석·학습을 요청하면:
1. 포맷을 모르면 묻는다. yt-dlp가 없으면 동의 후 `~/.local/share/fcp-autocut/bin/fcp setup --youtube`.
2. `~/.local/share/fcp-autocut/bin/fcp learn add "<링크>" --format vlog` (화면 전환 속도까지 보려면 `--video`).
   받은 오디오는 임시로만 쓰고 지워진다. 모델 다운로드 규칙은 받아쓰기와 같다.
3. 출력된 `VIDEO_JSON`을 읽는다(대본 `stats.text`, 직접 올린 자막 `subtitle_text`, 설명, 챕터).
4. `~/.local/share/fcp-autocut/channel/채널노트.md`를 만들거나 갱신한다:
   주제·말투·자주 쓰는 오프닝/마무리 멘트·동행자·고유명사·편집 리듬(문장 사이 멈춤, 남겨 두는 군말)·
   이 채널에서 '살려야 하는 말'의 특징. 영상이 쌓일수록 공통점 위주로 다듬는다. 추측은 추측이라고 적는다.
5. `~/.local/share/fcp-autocut/bin/fcp learn summary`로 설정값 제안·고유명사 후보를 보고, **사용자에게 보여 주고 동의를 받은 뒤에만**
   `~/.local/share/fcp-autocut/my_presets.yaml` / `my_vocab.txt`에 반영한다(기본 파일은 고치지 않음).
- 할 수 있는 것: 완성본의 말 리듬·멈춤 길이·남긴 군말·자주 쓰는 표현·오프닝/마무리 패턴·화면 전환 빈도.
- 할 수 없는 것: 화면 내용(무엇이 찍혔는지) 이해, 비공개·멤버십 영상, 원본 없이 "무엇을 잘랐는지" 알아내기.

## 문제 해결
- 파이널컷에서 클립이 빨간 화면 → 원본을 옮겼거나 이름이 바뀜. 원래 위치로 되돌리거나 파이널컷의
  "파일 다시 연결"을 안내.
- 규격 검사 실패 → 오류 내용을 읽고 원인을 고친다(사용자에게는 "파일 형식을 고치는 중"이라고만).
- 받아쓰기가 너무 틀림 → 시끄러운 현장일 가능성. 경고 수치를 알려 주고 vocab.txt 보강 제안.
- 테스트: `"${PY}" -m pytest "${SK}/tests" -q` (pytest는 `setup.sh --dev`)
